# M4 架构与迭代分析

日期：2026-10-15。范围：当前 M4 源码及仓库默认 `config/configs.yaml`。用户暂时无法提供稳定版 checkpoint 的实际配置，因此本文中的维度和超参数不代表线上配置已被核实。稳定性来自用户的实际使用反馈；下文对其原因和改进收益的解释属于待验证假设。没有改动模型实现、加载真实权重或运行训练实验。

## 1. 定位

M4 是结合气象与外部时序模型预测的联合 patch Transformer。它保留 PatchTST 的分块编码思路，但已经改为变量之间共同参与注意力，不能简单等同于原始 channel-independent PatchTST。

可以将其理解为：用历史功率辨认近期运行状态，用历史/未来气象提供天气条件，用 Chronos 给出未来功率先验，再由一个联合网络直接生成整段功率曲线。它能够隐式修正 Chronos，但当前输出并没有 `Chronos + residual` 这样的显式跳连。

## 2. 默认配置下的实际数据流

```text
general_ghi[672]  + general_ghi_predict[192]  → 辐照通道[864]
general_temp[672] + general_temp_predict[192] → 温度通道[864]
observe_power[672] + chronos[192]             → 功率通道[864]
             ↓ 每个通道在完整 864 点上做 RevIN
      [B, 3, 864]
             ↓ patch_len=stride=96，无重叠
      [B, 3, 9, 96]
             ↓ 共享 Linear(96, 256)
      [B, 3, 9, 256]
             ↓ 合并“变量 × 时间 patch” + 可学习位置嵌入
      [B, 27, 256]
             ↓ 4 层联合自注意力，4 heads，FFN 1024
      [B, 3, 256, 9]
             ↓ 全展平
      6912 → 256 → 256 → 64 → 192
             ↓ 使用功率通道的 RevIN 统计量还原
      logits[B, 192]，真实功率单位
```

依据：`transformer_models.py::forward`、`layers/PatchTST_backbone.py::TSTiEncoder.forward` 和 `Flatten_Head_new`。

关键细节：

- 每个 patch 覆盖 24 小时，但从滑动窗口起点分块，不一定对应自然日。
- 7 个历史 patch 和 2 个未来 patch 恰好分开，默认配置没有跨历史/未来边界的 patch。
- `TSTiEncoder` 虽然保留“channel-independent”的名字/注释，实际 reshape 为 `[B,C*N,D]`，而不是 `[B*C,N,D]`。
- 27 个 token 做全局双向注意力；未来 NWP 和 Chronos 是已知预测输入，只要在起报时刻可用，这种注意力本身不构成标签泄漏。
- 位置嵌入绑定变量顺序与相对 patch 位置；没有显式时钟、季节、变量类型、来源或缺测标记输入。
- 主干默认 Post-Norm + BatchNorm，输出头用 LayerNorm；支持跨层 attention score 残差。
- 最终 192 点一起输出，不是逐点自回归，因此单次 192 点预测没有递归累积误差；业务侧滚动扩展是另外的过程。
- 输出 `embeddings` 是第一层线性变换后、LayerNorm/ReLU 前的 256 维值。
- 默认是点预测；旧的“9 分位损失”已注释，而且当前输出也没有独立的分位维度。

按线性层、注意力、归一化和位置参数计算，默认网络可训练参数约 506 万（未计未提供的外部损失组件可能存在的参数），其中输出头约 187 万，占约 37%。这是源码公式计算，不是实例化后的实测统计。

## 3. 当前设计为什么可能稳定

这些解释与结构吻合，但不能替代消融结果：

1. Chronos 给出未来曲线先验，减少完全由天气到功率映射的学习负担。
2. RevIN 降低不同窗口的尺度差异。原始 RevIN 设计就是先消除实例均值/方差差异，再在输出恢复尺度。[作者项目页](https://seharanul17.github.io/RevIN/)
3. 24 小时 patch 与较短的 token 序列，使主干倾向于利用跨日形状和天气关系。
4. 输出头压缩和 dropout 带来较强约束，可能有利于有限数据下的方差控制。
5. 三个输入通道数量适中，避免模型一开始面对过多噪声气象字段。

这些是值得保留的结构特征；不应只因更换骨干更“新”就整体推翻。

## 4. 最有依据的迭代空间

### 4.1 输出头有明确的表示约束

最终线性层为 `Linear(64,192)`。在反归一化前：

`y_norm = W h64 + b`。

因此每条归一化预测曲线都落在维度至多 64 的固定仿射子空间中；外部 RevIN 的缩放/平移会改变真实单位输出，不能直接把该限制照搬为原始功率曲线的同一仿射子空间。

这不是“不能输出尖峰”的证明——线性基底也可以表示尖峰——但它确实限制了可独立表达的曲线变化。重要的是：把 `embedding_dim` 从 256 加到 512 并不能消除末端固定的 64 维限制。

最干净的验证是只把末端隐藏维度 64 改为 128 或 256，保留其它结构，观察高变率日、峰值和短时效误差。如果没有稳定收益，说明这个约束在当前数据上可能恰好起到有效正则作用。

更有针对性的改进是逐时刻解码：把全局表示、未来 patch 表示、该时刻 NWP、先验功率和时间特征送入共享输出头，使对应时刻的天气能直接影响对应输出。TiDE 的 temporal decoder 使用了这种未来协变量直达输出的路径；这是结构参考，不是它在本项目必然提升的证据。[TiDE §4.2](https://arxiv.org/html/2304.08424v4#S4.SS2)

### 4.2 24 小时 attention 粒度与短时效需求不同

当前 96 点 patch 经 96→256 的投影，并未必然丢掉 patch 内所有细节。准确的限制是：attention 在整块之间建立关系，没有独立的 15 分钟 token 来专门对齐最近几小时与未来局部天气。

可先测试 patch/stride 48，再视结果测试 24；也可保留日尺度分支，增加近 4–12 小时的细粒度局部分支，重点纠正未来前 16 点。

需要控制混杂：patch 从 96 改为 48 时 token 从 27 增到 54，attention 矩阵元素变成 4 倍，同时 flatten head 的输入翻倍，第一层头参数也近乎翻倍。不能把收益全归因于时间粒度；应记录参数、显存和耗时，必要时使用共享逐步头或做等参数对照。

原始 PatchTST 的关键设计是 patching 与 channel-independence；M4 已主动改变后者，因此不应直接照搬原论文的参数结论。[PatchTST 原论文](https://arxiv.org/abs/2211.14730)

### 4.3 RevIN 保留形状，也隐藏了一部分物理幅度

天气均值/标准差由历史+未来共 864 点计算，归一化后的天气进入网络，但天气均值/标准差没有作为旁路特征送入输出头。整段辐照近似正仿射变换后，归一化形状可非常接近，而相同历史功率下未来绝对辐照水平仍可能影响功率预测。

功率的均值/标准差同样在“672 点实测 + 192 点 Chronos”上计算，因此 Chronos 改变既影响未来 token，也影响整个功率通道的归一化和输出还原尺度。这不是使用未来真值的泄漏，但确实把外部先验和尺度基准耦合起来。

建议按单变量消融顺序验证：

1. 保留 RevIN，额外向头部提供天气均值/标准差或固定物理缩放后的未来天气。
2. 只改变功率统计：统计量来自历史实测，用同一统计量归一历史与未来提示，再还原输出。
3. 单独比较功率容量归一化；只有站点容量口径可靠时才进行，并与损失口径分别记录。

不能直接断言移除 RevIN 更好。历史全零、整周低出力等窗口也需要显式尺度下限和缺测处理。

### 4.4 先验预测应有来源、置信度和失效处理

当前历史实测与未来 Chronos 共用一个功率通道，边界通过固定位置间接表达。没有显式来源标记、提示缺失标记、提示 dropout 或误差置信度。

可以保留拼接设计，增加 history/future、observed/predicted、missing 等标记；训练时再引入可控的提示噪声/缺失模拟。需要先定义缺失后的替代值和 mask，不能直接把未来提示置零而仍让混合 RevIN 统计发生无意变化。

更换 Chronos 为 TimesFM 时，单纯替换输入列会同时改变先验质量和输入分布。应分开比较底座单独预测、原 M4、使用新先验重新训练的 M4；不可将旧 checkpoint 换列的结果直接作为架构结论。

## 5. 我建议的 M4.1：保留原模型，加轻量逐步纠错

如果目标是尽量保留当前稳定性，优先考虑：

`y_new[t] = y_m4[t] + C * delta[t]`

`delta[t] = Head(global_context, local_context, future_nwp[t], prior[t]/C, time_features[t], masks[t])`

其中 C 是可靠的站点容量，delta 是归一化功率修正。若容量不可用，需要明确采用其它仅依赖可见输入的尺度。

第一阶段冻结原 M4，并固定其 BatchNorm/Dropout 为推理态；新分支最后一层权重和 bias 置零，让初始输出与原 M4 一致，再训练修正分支。不能只冻结参数却让 BatchNorm running statistics 继续更新。零初始化只保证初始一致，不保证训练后不会退化，仍需验证集选点。

为便于解释，第一版只使用 M4 全局表示和未来 NWP/先验/时钟，不同时加入局部分支、多个新气象源与新损失。随后再单独测试最近历史编码，或小学习率联合微调。

这条路线让新分支直接处理旧模型未解释的误差，避免在第一轮实验中同时重学已有的全部映射。另一条独立路线是从头训练“Chronos + residual”的 M4，但它围绕 Chronos 而非现有 M4 保持基线，两者不能混为一个实验。

## 6. 训练与数据契约中的混杂因素

这些问题影响能否判断架构优劣，应与结构试验分开修正：

| 项目 | 当前源码事实 | 分析含义 |
|---|---|---|
| 验证选点 | `M4_build_training_args` 未启用 eval strategy，`load_best_model_at_end` 注释，无 early stopping callback | 设置 `metric_for_best_model` 和局部 patience 不代表已经按验证指标选最优；公共入口通常保存训练末态 |
| 种子 | YAML 的 `optimization.random_seed` 未传入此处 TrainingArguments；公共入口显式设种子代码被注释 | 当前配置项不是完整复现保证；模型构造前初始化种子也要核对 |
| 其它无效旋钮 | `d_layers/factor` 未用于当前主干；`fc_dropout` 默认 flatten 分支未使用；`individual` 不改变当前头；`lradj/pct_start/patience` 未按 YAML 接入此训练器 | 调这些键不一定改变实际实验 |
| 输入列 | M4 默认 `tsfm_col=chronos`；公共入口缺省 feature_cols 使用 `observe_power_chronos_pred` | 当前默认组合需要显式对齐，不代表线上使用了错误配置 |
| 容量 | 公共入口缺省 feature_cols 不含 `cap_power_on` | 即便原表有容量，也可能在 Dataset 阶段丢失，触发损失 fallback |
| 容量 fallback | `torch.max(y_true, ones_like(y_true))` 是逐点 max(y,1)，并非沿时间取最大值，也非站点容量 | 会把主损失变成按瞬时真实功率缩放的误差，明显改变低出力时段权重 |
| 容量维度 | loss 仅显式处理一维 batch 容量；其它二维/序列形态未统一 | `[B,1]`、`[B,H]` 等形态存在广播风险，应标准化成明确形状再计算 |
| 外部南网损失 | `PVNormalizedLoss` 的源文件未随本目录提供 | 只能确认调用了该组件，不能宣称其公式与公共 NanwangMetric 完全一致 |
| 缺测 | M4 内部没有显式有限值 mask；RevIN 使用普通 mean/var | 依赖上游提供有限输入；坏点可能污染整窗，而非仅影响一个输出点 |

当前默认主损失是容量归一 MAE，再以 100 和 50 加权主损失与外部南网损失。实际主损失输入是反归一化后的功率；`compute_loss` 的部分 docstring 仍描述旧逻辑，应以执行代码为准。

损失和选点还应区分全 192 点、超短期前 16 点与 D+1 窗口。`[55:151]` 仅是 10:00 起报下的次日窗口，不能对所有起报时刻硬套固定索引。

## 7. 最小实验顺序

| 编号 | 相对参照唯一改动 | 要回答的问题 |
|---|---|---|
| B0 | 核实可运行的当前 M4 与实际输入/容量/种子配置，固定切分 | 获得能复现的原始参照 |
| B1 | 相同网络与损失，加入真实业务验证选点 | 有多少差距来自训练末态而非架构？ |
| H1 | 基于 B1，仅末端隐藏 64→128 | 输出维度约束是否限制效果？ |
| H2 | 基于 B1，仅加入未来逐步 NWP 纠错分支 | 天气直达输出是否改善细节？ |
| N1 | 基于 B1，仅将功率 RevIN 统计改为历史段 | 先验与尺度耦合是否有害？ |
| P1 | 基于 B1，仅 patch/stride 96→48，记录参数增长 | 更细时间粒度是否值得成本？ |

容量、字段等契约如果需要改正，保留改正前后的结果记录，形成新参照后再开展结构比较。不要把所有修复混进 H2。

每个正式候选至少用固定的多种子配对比较，记录站点均值、站点分数变化、最差分位表现、季节、已见/未见站、昼夜、晴/阴/高变率、前 16 点与 D+1。按站/按日做配对统计，避免把高度重叠起报窗口当成独立样本来夸大显著性。

先在验证集确认收益，再选少量组合并在独立测试上验收；同时衡量低分站退化和异常天气鲁棒性，以保护“稳定”这一已有优势。不建议第一轮直接增加 Transformer 深度、扩大 d_model、替换新骨干或同时加入全部 NWP 字段。

## 8. 结论与边界

M4 有明确迭代空间，最值得关注的是“全局表征如何转成局部预测”“绝对天气幅度如何保留”“近期状态如何影响短时效”以及“先验如何被可靠利用”。

优先保留跨变量 patch attention 与外部预测先验，先建立可复现验证基线，再尝试逐步纠错和末端头部消融。本文没有分站误差或 checkpoint 实测，因此不承诺具体分数增益，也不据代码直接判定其中某项是当前实际瓶颈。
